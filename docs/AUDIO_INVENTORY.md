# Audio inventory

Last audited: 26 July 2026  
Application version: 0.10.3

## Policy

Every packaged MP3 must:

- decode successfully with FFprobe/FFmpeg,
- have a positive duration,
- contain an audible signal above the `-70 dB` maximum-volume threshold,
- not be an exact byte-for-byte duplicate of another packaged MP3,
- be referenced by the active music, ambient or SFX configuration.

Effects without an approved file use a named Web Audio implementation from `src/audio/synthSFX.ts`. They must not request a missing file before using synth audio.

The permanent CI gate runs:

```bash
node scripts/audit-audio.mjs --fail-on-silent --fail-on-duplicates
```

## Removed measured placeholders

The audit found one invalid 3,962-byte payload copied to 21 unrelated filenames: five ambient loops and sixteen SFX. FFprobe could not decode the payload. All copies were removed.

`study.mp3` was also removed because it was byte-for-byte identical to `menu-close.mp3`; Study now uses its distinct procedural effect.

## Provenance and licensing

### Runtime synth effects

The procedural effects are generated by project code in `src/audio/synthSFX.ts` and are covered by the repository's code licence.

### Packaged MP3 files

The remaining MP3 files predate this audit. Their original creator, source URL and asset-specific licence are **not recorded in the repository**. They are retained because they are active existing project assets, not because this audit established third-party redistribution rights.

Before distributing the audio separately, selling an asset pack, or publishing on a platform that requires explicit media provenance, the project owner should add one record per source or collection containing:

- creator/provider,
- source URL or original project file,
- licence or ownership statement,
- attribution requirements,
- date obtained.

Do not invent attribution where the source is unknown.
